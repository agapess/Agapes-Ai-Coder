How should code execution work under the hood?

Three approaches — different power levels, different complexity

Execution flow
▶ Run
→
exec(cmd)
→
wait...
→
output
Result appears all at once when done.
No streaming. Timeout after 30s.

Pros

  • Simple to build
  • No WebSocket needed
  • Works with existing API

Cons

  • No streaming output
  • No stdin (can't answer prompts)
  • Feels slow for long tasks

A — Simple Exec (collect then show)

Run command, wait for it to finish, display all output at once. Uses existing HTTP POST endpoint. Fast to build, limited feel.

Execution flow
▶ Run
→
spawn()
→
SSE stream
→
live output
Output streams line by line in real-time.
⏹ Stop button kills process.

Pros

  • Real-time streaming output
  • Stop button works
  • Reuses SSE pattern (already in FORGE)

Cons

  • No stdin (can't type input)
  • No interactive programs
  • Colors may not render

B — Streaming Spawn (recommended)

Spawn process, stream stdout/stderr via Server-Sent Events line by line. Real-time feel, Stop button, no extra dependencies. FORGE already uses SSE for AI streaming.

Execution flow
▶ Run
→
node-pty
→
WebSocket
→
xterm.js
$ python script.py
Enter your name: █
Hello, Ali!

Pros

  • Full terminal (stdin, colors, ANSI)
  • Interactive programs work
  • Real shell experience

Cons

  • Needs node-pty (native module)
  • Needs xterm.js on frontend
  • WebSocket setup complexity
  • node-pty can be painful on Windows

C — Full PTY Terminal (node-pty + xterm.js)

Real pseudo-terminal — ANSI colors, cursor control, stdin, interactive programs. The full VS Code terminal experience inside FORGE. Significant extra dependencies.
