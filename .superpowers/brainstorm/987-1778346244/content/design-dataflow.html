Execution Data Flow

What happens from click → output, for both web and server-side code

SERVER-SIDE (Python, Node, Bash…)
1. USER CLICKS RUN
useExecution detects language from active file extension (.py → python). Opens WebSocket to ws://localhost:3001/terminal
2. WS HANDSHAKE → SPAWN
Backend receives connection. Writes file content to temp path in project dir. Spawns node-pty: python script.py in project working directory.
3. LIVE I/O PIPE
PTY stdout/stderr → WebSocket → xterm.js (rendered in real-time). xterm.js keystrokes → WebSocket → PTY stdin. Full bidirectional, ANSI colors preserved.
4. PROCESS EXIT
PTY exit event fires. Backend sends {"type":"exit","code":0} over WS. Frontend shows exit badge, disables Stop. WS closes cleanly.
STOP / TIMEOUT
Stop button → WS sends {"type":"kill"} → backend kills PTY process. Also auto-kills after 60s timeout.
WEB FILES (HTML/CSS/JS)
1. USER CLICKS RUN
HTML file detected. No WebSocket needed. Existing Preview iframe is refreshed. Console interceptor script is injected before page renders.
2. INTERCEPTOR INJECTED
A small script overrides console.log/warn/error and window.onerror inside the iframe. Each call is PostMessaged to the parent frame.
3. POSTMESSAGE → TERMINAL
Parent window listens for messages. Each console event is formatted and written to the TerminalPane — same UI as server-side output. Errors show in red, warnings in yellow.
RUNTIME ERRORS
window.onerror and unhandledrejection are also captured. Stack traces are formatted and sent to TerminalPane. The preview still shows even if JS errors occur.
WEBSOCKET MESSAGE PROTOCOL
Client → Server
{"type":"start","file":"script.py",
 "content":"...","lang":"python"}
{"type":"input","data":"hello\n"}
{"type":"kill"}
{"type":"resize","cols":80,"rows":24}
Server → Client
{"type":"output","data":"Got 42..."}
{"type":"exit","code":0}
{"type":"error","message":"python not found"}
